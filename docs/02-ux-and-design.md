# 02 体験、画面、デザイン

## 2.1 体験の流れ

利用者は、知らなかったゲームを見つけ、どのような遊びを楽しめるかを把握し、公式ストアや元記事へ進む。

主な導線は次のとおり。

```
ホーム ─┬─ 最新情報のカルーセル（記事） ─────┐
        ├─ 最近収録した作品 / 情報が充実した作品 ─┤
        ├─ コレクション ── コレクション詳細 ───┼─→ 作品詳細 ─┬─→ 公式ストア（外部）
        └─ 検索ボックス ── 作品一覧と検索 ─────┘             ├─→ 元記事（外部）
                                                             └─→ 関連作品 → 作品詳細
```

- 「新しく収録した日（収録日）」と「発売日」は常に別の項目として表示する。以前に発売された作品も、収録日が新しければ「最近収録」に並ぶ。
- サイトの表側ではゲームの魅力と探しやすさを優先する。LLM による運営方式の説明は運営説明ページ（`/about/`）にまとめる。

## 2.2 URL 一覧

すべての URL は `BASE_PATH` の配下に置く（[08-hosting-and-migration.md](08-hosting-and-migration.md)）。末尾にはスラッシュを付ける（`trailingSlash: 'always'`）。

| URL | 画面 | 生成方法 |
| - | - | - |
| `/` | ホーム | 静的 |
| `/games/` | 作品一覧と検索（1ページ目） | 静的。JS で検索 UI に切り替わる |
| `/games/page/{n}/` | 作品一覧の2ページ目以降 | 静的。JS が無効な環境のためのページ送り |
| `/games/{gameId}/` | 作品詳細（例: `/games/g_000123/`） | 静的。公開中の作品ごと |
| `/games/{mergedGameId}/` | 統合済みの旧 ID からの転送ページ | 静的。meta refresh と canonical で統合先へ案内する |
| `/articles/` | 記事一覧（新しい順、1ページ30件） | 静的 |
| `/articles/page/{n}/` | 記事一覧の2ページ目以降 | 静的 |
| `/articles/kind/{kind}/` | 記事の種別ごとの一覧（2ページ目以降は `/page/{n}/` を付ける） | 静的 |
| `/collections/` | コレクション一覧 | 静的 |
| `/collections/{collectionId}/` | コレクション詳細（例: `/collections/col_0001/`） | 静的 |
| `/events/` | イベントの一覧。会場で開くイベント（月ごと）を大きく、オンラインのイベントを1行ずつ小さく並べる。最近終わった会場のイベントは分けて見せ、それより前に終わったものは折りたたむ | 静的 |
| `/events/{eventId}/` | イベントの詳細（日程、会場、案内のページ、行った人と出展した人の感想、記事、出展作品） | 静的。公開中の催しごと |
| `/about/` | 運営説明 | 静的（Markdown） |
| `/404.html` | 見つからないページ | 静的 |
| `/build-manifest.json` | 公開成果物の manifest | ビルド時に生成（[07](07-workflows-and-operations.md) §7.4） |
| `/media/articles/{articleId}.webp` | 記事の OGP 画像 | `npm run media:articles` で保存し、`public/` から配信 |
| `/sitemap-index.xml`、`/robots.txt` | クローラー向け | ビルド時に生成 |
| `/pagefind/` | 検索索引 | Pagefind が生成 |

URL には作品の表示名や slug を含めない。タイトルが変わっても URL は変わらない（[04-data-model.md](04-data-model.md) §4.2）。

## 2.3 画面ごとの仕様

### 2.3.1 共通レイアウト

- ヘッダー: ロゴ（Indie Atlas）、主要ナビゲーション（作品、記事、コレクション、運営説明）、検索ボタン（`/` キーで検索ページの入力欄へ移る）、表示テーマの切り替え（ライト、ダーク、システム設定に従う）。
- フッター: 運営説明へのリンク、出典と画像の扱いについての短い説明、情報の訂正依頼の窓口（[11](11-open-decisions.md) の D-10）、最終更新日。
- スキップリンク（「本文へ移動」）を先頭に置く。
- `<html lang="ja">` を指定する。外国語の原題や記事タイトルには、該当する要素に `lang` 属性を付ける。

### 2.3.2 ホーム（`/`）

ホームは「今」動いているものを見せる。上から次の順に並べる（2026-11-07 に変更）。

| 区画 | 内容 | 件数・並び順 |
| - | - | - |
| 最新情報 | 画像に見出しを重ねた記事の枠。大きな枠1件（左の2列と2行）と、その右の4件、下の行の4件を、切り替えずに一度に並べる（2026-11-08 にカルーセルをやめた）。記事の OGP 画像、種別、言語の印、媒体名、掲載日、見出し | 種類と作品の知名度で点を付けた9件 |
| 今日のピックアップ（左） | 作品1件を大きく（画像、開発元、発売状況、紹介文、タグ、スクリーンショット4枚まで）、その作品を扱う記事を見出しと短い説明で添える。右のイベントの欄と高さをそろえ、余った高さはスクリーンショットの段が使う。続く2件は小さく、記事の見出しを1件添える | ビルドした日（日本時間）ごとに選び直す（§2.3.2a） |
| イベント（右の細い列） | 会場で開くイベントを小さな画像付きで。終わったばかりで感想や記事のある会場のイベントを、件数とともに。オンラインのイベントは1行ずつ | 会場4件、終わったばかり2件、オンライン3件。期間が3日を超える催しは出さない |
| 記事 | 画像を左に置いた横長の記事のカード（画像、種別、言語の印、媒体名、掲載日、見出し3行まで、原題、扱う作品）を2列。狭い画面では1列 | 最新情報とピックアップに出していない新しい記事20件 |
| 最近収録した作品 | 作品カード | `addedAt` の新しい順に5件（1行） |
| 情報が増えた作品 | 作品カードと、充実した内容の短い表示（例:「発売日が更新」「日本語対応を確認」） | `enrichedAt` の新しい順に5件。最近収録した作品の区画に出した作品は除く |
| コレクション | コレクションカード | `featured: true` のものを優先し、足りなければ更新の新しい順で補う。4件 |
| 売れ筋 | Amazon の売れ筋か、Steam のインディーの売上上位 | 10件 |

#### 2.3.2a 今日のピックアップの選び方

- 候補は、画像、紹介文、見出しを表示できる関連記事のそろった公開中の作品。
- サイト用データを作るときに、日付と作品の ID のハッシュから乱数を作り、重み付きで抽出する（`scripts/build/site-data.ts` の `dailyPicks`）。重みは、最も新しい関連記事が90日以内なら新しいほど大きく、関連記事が多いほど少し大きい。同じ日なら何度作っても同じ結果になる。
- 前の日と同じ作品は先頭にしない。最新情報の大きな枠で扱っている作品は除く。
- 選んだ結果は `.generated/site-data/picks.json` に入る。日付が変わると公開内容ハッシュが変わり、毎日公開し直される。

`enrichedAt` の定義は [04-data-model.md](04-data-model.md) §4.9 にある。

### 2.3.3 作品カード（共通部品）

| 要素 | 内容 | 値がない場合 |
| - | - | - |
| 画像 | ヘッダー画像。縦横比は 460:215 に固定し、`object-fit: cover` で収める | 共通のプレースホルダー画像 |
| 表示名 | `title.display` | （必須項目） |
| 原題 | 表示名と異なる場合だけ小さく表示する。`lang` 属性を付ける | 表示しない |
| 開発者 | 最初の1名。2名以上なら「ほか」を付ける | 「開発者不明」 |
| 発売 | 全体の発売状況のラベル（§2.4.2） | 「発売時期不明」 |
| 機種 | 機種アイコン（最大4つ、超えた分は「+n」） | 表示しない |
| 日本語対応 | バッジ（対応、一部、非対応、不明） | 「日本語: 不明」 |
| 収録日 | 「収録 2026/10/27」 | （必須項目） |

カード全体を作品詳細へのリンクにする。カード内に別のリンクを入れ子にしない。

### 2.3.4 作品一覧と検索（`/games/`）

- JS が無効な環境では、静的な一覧（収録日の新しい順、1ページ48件、ページ送り付き）を表示する。
- JS が有効なら、同じ場所を検索 UI に置き換える。
  - 入力欄: タイトル、原題、別名、読み、開発者名、タグ名、概要を対象にする。
  - フィルター: タグ（複数選択）、機種（複数選択）、発売状況、日本語対応、プレイ形式。
  - 並び順: 関連度（入力がある場合の既定）、収録日の新しい順（入力がない場合の既定）、発売日の新しい順。
  - 入力が空でもフィルターだけで一覧を出す（Pagefind の `search(null, { filters })`）。
  - 状態を URL のクエリと同期し（`?q=…&tag=roguelike&platform=switch`）、共有と戻る操作に対応する。`history.replaceState` を使い、入力のたびに履歴を増やさない。
- 結果は作品カードと同じ見た目にする。0件のときは条件の緩め方を提示する（フィルターを1つずつ外すボタン）。
- 検索の実装方法は [03-architecture.md](03-architecture.md) §3.6 にある。

### 2.3.5 作品詳細（`/games/{gameId}/`）

| 区画 | 内容 |
| - | - |
| ヘッダー | キーアート、表示名、原題、主な別名、開発者、パブリッシャー、全体の発売状況、ストアへのボタン（主要な操作）、公式サイトへのリンク |
| 概要 | 出典に基づく概要（60〜160字）。下に「出典」として参照元を列挙する |
| 特徴 | 3〜5項目の箇条書き。出典を併記する |
| 基本情報 | 表形式。開発、パブリッシャー、タグ、機種、発売（機種と地域ごと）、日本語対応（表示、字幕、音声）、プレイ人数と形式、公式サイト。行ごとに出典へのリンクと確認日を付ける |
| 発売情報の変遷 | 延期などで置き換わった発売情報を、時系列で折りたたみ表示する（ある場合のみ） |
| 関連記事 | 記事の種別（発表、ニュース、紹介、レビュー、インタビュー、開発日誌など）ごとにまとめる。各記事に媒体名、掲載日、言語、作品の扱い（主題、言及、まとめ記事内の紹介）、原文へのリンクを付ける |
| 関連作品 | 最大6件。各作品に関連の理由を一文で付ける |
| 収録コレクション | この作品を含むコレクション |
| ページ情報 | 収録日、ページの最終更新日、「情報の誤りを報告」 |

表示上の規則は次のとおり。

- 未確認の項目は推測で埋めず、「不明」と表示する（§2.4.3）。
- 概要と特徴の近くに「複数の出典をもとに要約した紹介です」と注記し、運営説明へリンクする。プレイしたかのようなレビューの文体は使わない（[05](05-sources-and-editorial-policy.md) §5.6）。
- 記事は原題のまま表示し、`lang` 属性を付ける。当サイトが書いた短い説明（120字以内）は、情報源の権利条件が許す場合だけ表示する。
- 構造化データとして JSON-LD の `VideoGame` を出力する。項目は `name`、`url`、`image`、`gamePlatform`、`author`（開発者）、`publisher`、`datePublished`（日単位で発売済みと確定している場合だけ）とする。

### 2.3.6 記事一覧（`/articles/`）

- 掲載日の新しい順に、1ページ30件を表示する。
- 各行に、記事タイトル、媒体名、掲載日、記事の種別、関連作品（最大3件と「+n」）、原文へのリンクを表示する。
- 日本語以外の記事には言語の印（「英語」など）を付け、訳したタイトル（§2.4.5）を大きく、原題を小さく添える。
- 2列で並べるときは、記事を左右の列に交互に積む（行で揃えると、長い記事の横の列に隙間が空くため）。1列になる狭い画面では元の順に並べる。
- 種別のタブ（すべて、発表、ニュース、紹介、レビュー、インタビュー、開発日誌、特集、まとめ）は静的なページ（`/articles/kind/{kind}/`）へのリンクにする。
- 媒体や言語での絞り込みは第4段階以降に検討する。

### 2.3.7 コレクション一覧と詳細

- 一覧: コレクションカード（タイトル、短い説明、代表作品3件の画像、作品数）を並べる。
- 詳細: タイトル、説明（Markdown）、選定条件、作品の一覧を表示する。作品ごとに、コレクションに含めた理由を一文で付ける。並び順はコレクションの `order` に従う。

### 2.3.7a イベント（`/events/`、`/events/{eventId}/`）

- 会場で開くイベント（`format` が `in-person` か `hybrid`）とオンラインのイベント（配信の発表会、ストアのフェスとセール）をはっきり分ける。会場のイベントは画像、日付、名前、会場、説明を大きく見せ、国内と海外で絞り込める。オンラインのイベントは月ごとに1行ずつ並べる。
- 会場のイベントには形式のラベル（「会場」「会場・配信」）を付ける。会場がまだ分からないものは「会場未定」と表示する。
- 名前はイベントの詳細へのリンクにする。案内のページ（公式サイト）と Google カレンダーへの追加は外部へのリンクとして別に置く。
- 終わってから30日以内の会場のイベントは「最近終わったイベント」として分けて見せる。感想と記事の件数を表示する。
- 詳細には、日程、会場、説明、公式サイト、出典に加え、行った人と出展した人の感想（個人のブログや note の記事の画像、見出し、書き手、サービス名、掲載日。原文へのリンク。広い画面では2列）、見出しにこの回の名前がある記事、出展作品を並べる。感想の集め方は [06](06-update-pipeline.md) §6.13.8。

### 2.3.8 運営説明（`/about/`）

`src/content/about.md` に置き、少なくとも次の内容を書く。

1. Indie Atlas の目的と収録対象（インディーと判定する方法を含む）
2. 情報の集め方。LLM が毎日自動で調査し、決定的な検証を通った情報だけを掲載していること
3. 概要や特徴の文章は出典をもとに自動で要約したもので、プレイした感想ではないこと
4. 出典、記事、画像の扱い（原文へのリンクを基本とし、全文は転載しないこと）
5. 「不明」の意味と、確認日の意味
6. 訂正依頼と掲載停止依頼の窓口
7. 運営者の連絡先

## 2.4 表示ルール

### 2.4.1 日付

| 対象 | 表示形式 | 例 |
| - | - | - |
| 収録日、確認日、掲載日 | `YYYY年M月D日`（カードでは `YYYY/MM/DD`） | 2026年10月27日 |
| 発売日（日まで分かる） | `YYYY年M月D日` | 2026年3月5日 |
| 発売日（月まで） | `YYYY年M月` | 2026年3月 |
| 発売日（四半期） | `YYYY年 第N四半期` | 2027年 第2四半期 |
| 発売日（半期） | `YYYY年 上半期` / `下半期` | 2027年 上半期 |
| 発売日（季節） | `YYYY年 春` など。出典の原文表記（`rawText`）も保持する | 2027年 春 |
| 発売日（年） | `YYYY年` | 2027年 |
| 発売日未定 | 「発売日未定」 | |

日付は日本時間（Asia/Tokyo）で表示する。保存は UTC の ISO 8601 で行う（[04](04-data-model.md) §4.1）。

### 2.4.2 発売状況のラベル

| 状態 | ラベル | 全体の状況を決める優先順位 |
| - | - | - |
| `released` | 発売中（`YYYY年M月D日` 発売） | 1（いずれかの機種で発売済みなら全体を発売中にする） |
| `early-access` | 早期アクセス中 | 2 |
| `upcoming` | 発売予定（`2027年 春`） | 3（最も早い予定日を表示） |
| `tba` | 発売日未定 | 4 |
| `cancelled` | 開発中止 | 5（全機種が中止の場合だけ） |
| `delisted` | 配信終了 | 6（全機種が配信終了の場合だけ） |

### 2.4.3 不明と未確認の表示

- 採用済みの Claim がない項目は「不明」と灰色の文字で表示する。空欄にも、推測した値にもしない。
- 「非対応」は根拠がある場合だけ表示する。根拠がなければ「不明」にする。
- 矛盾した情報がある項目でも、採用済みの値があればその値を表示し続ける。採用済みの値がないまま矛盾している項目だけを「確認中」と表示する（[06](06-update-pipeline.md) §6.8.2）。他の項目はそのまま表示する。

### 2.4.4 外部リンク

- 記事、ストア、公式サイトへのリンクは `target="_blank" rel="noopener"` にし、外部リンクであることをアイコンと読み上げ用のテキスト（「新しいタブで開く」）で示す。媒体に参照元を伝えるため、`noreferrer` は付けない。
- アフィリエイトリンクは使わない。

### 2.4.5 日本語以外の記事の見出し

- 日本語以外の記事には、どの画面でも言語の印（「英語」など）を付ける。
- 訳したタイトル（`titleJa`）があれば、それを見出しとして出し、`lang="ja"` を付ける。原題は一覧と詳しい表示で小さく添え（`lang` は記事の言語）、画像に見出しを重ねる枠では省く。訳がなければ原題を出す。
- 訳は LLM が作る（[06](06-update-pipeline.md) §6.13.9）。

## 2.5 デザインの考え方

### 2.5.1 コンセプト

「ゲームのメニュー画面」のような、シンプルでもわくわくする見た目を目指す（2026-10-28 に変更）。

- 地は墨色（ライトテーマは紙の色）。信号色の赤を面に、黄色を強調に使う。
- 角は丸めず、斜めに切り落とす。ボタン、タブ、タグは平行四辺形にする。
- 作品カードは、選ぶと信号色の影が飛び出し、見出しの前に選択のカーソル（▶）が出る。
- 見出しには番号と英字のラベルを付ける（例: `01 NEW ARRIVALS`）。
- 背景は WebGL のステージ（§2.7）。動きは遅く、本文は不透明な面に載せて読みを邪魔しない。

### 2.5.2 見やすさを守る規則

| 規則 | 内容 |
| - | - |
| 文字を動く背景の上に直接置かない | WebGL の上に文字を置く場合は、不透明度80%以上の面かぼかし付きの面を下に敷く。最も明るい背景の上でもコントラスト比を満たすことを確認する |
| コントラスト | 本文は 4.5:1 以上、大きな文字と UI 部品は 3:1 以上（WCAG 2.2 AA） |
| 動き | `prefers-reduced-motion: reduce` の環境では自動のアニメーションを止め、静止画の1フレームだけを描く。画面遷移の演出も切る |
| 情報の主従 | 演出よりも画像、タイトル、基本情報を優先する。WebGL は背景の装飾に限る（§2.7.2） |
| 1ページ1キャンバス | WebGL のキャンバスは1ページに1つまでにする。カードの演出は CSS で行う |

## 2.6 デザインシステム【初期案】

### 2.6.3 余白、角丸、影、動き

- 余白は 4px を単位にする: `--space-1`（4px）〜 `--space-12`（96px）

- 動き: 時間は `--dur-fast`（150ms）、`--dur-base`（250ms）、`--dur-slow`（400ms）。緩急は `--ease-out: cubic-bezier(0.2, 0.8, 0.2, 1)`

- 区切りの幅: 640px、1024px、1440px

### 2.6.5 画面遷移

ブラウザの文書間 View Transitions を段階的な強化として使う。

```css
@view-transition { navigation: auto; }
@media (prefers-reduced-motion: reduce) {
  @view-transition { navigation: none; }
}
```

一覧から詳細へ（と詳細から戻るとき）、作品の画像がつながって見えるようにする。画像には `data-vt-game="{gameId}"` だけを付けておき、`pageswap` と `pagereveal` で、押したカード（なければ画面内の同じ作品の1枚）と詳細のキーアートにだけ `view-transition-name: game-hero` を付ける。どちらかが画面の外にあるか、画像が読み込まれていなければつながない。名前を常に付けておくと、画面の外の画像が飛んできたり、同じ作品の画像が2枚あって遷移ごと取り消されたりするためである。

ほかの部分は次のように扱う。

- ヘッダーは `view-transition-name: site-header` にして重ねて切り替えず、そのまま置き換える。表示用のフォントは先読みし、`font-display: optional` にして、ページごとに代替のフォントへ切り替わらないようにする。`html` に `scrollbar-gutter: stable` を付け、スクロールバーの有無で幅がずれないようにする
- 背景の WebGL（§2.7）は、body の先頭の通常のスクリプトで、本文より先に最初の1枚を描く。前のページの色と波の位相を sessionStorage に残し、新しいページでは前の色から約0.9秒かけて移すクライアント側のルーター（Astro の `<ClientRouter />`）は使わない。WebGL と検索 UI の初期化を通常のページ読み込みと同じ流れで扱えるようにするためである。

## 2.7 WebGL の方針

2026-10-28 に、ホームのアトラス（作品を点で並べた地図）をやめ、ページ全体の背景を WebGL で描く方針に変えた（[11](11-open-decisions.md) の決定ログ）。

### 2.7.1 使う場所

| 場所 | 演出 |
| - | - |
| すべてのページの背景 | 「ステージ」。斜めに流れる信号色の帯、細い黄色の線、隅ほど大きくなる網点、霧のようなむら、粒子のノイズ。作品詳細では、作品の主ジャンルの色を混ぜる |
| ホームの最新情報 | カルーセル（§2.3.2）。WebGL は使わず、CSS の切り替えの演出だけにする |

### 2.7.2 実装の方針

- ライブラリは使わない。`src/scripts/gl/stage.ts` が WebGL2 を直接使い、全画面の三角形1枚とフラグメントシェーダーだけで描く。
- キャンバスは `position: fixed` で画面全体に置き、`aria-hidden="true"`、`pointer-events: none` にする。1ページに1つだけにする。
- 本文は不透明度93%の面（`main`）に載せ、動く背景の上に文字を直接置かない。背景が見えるのは、画面の左右の余白と面の切り欠きだけにする。
- 読み込み: body の先頭の通常のスクリプト（`src/scripts/gl/stage-boot.ts`）で、本文より先に始める（§2.6.5）。WebGL2 を使えない環境とデータ節約モードでは描かず、`body` の CSS の背景（斜めの帯と網点の静的な模様）のままにする。
- 動き: 帯はゆっくり流れ、ポインターの位置とスクロールでわずかにずれる。`prefers-reduced-motion: reduce` の環境では止まった1フレームだけを描く。
- 性能の保護: 背景は細部が不要なので、デバイスピクセル比を1以下で描く。タブが非表示のときは描かない。直近2秒の平均フレーム時間が 24ms を超えたら解像度を半分にし、それでも 33ms を超えたら止める。`webglcontextlost` でキャンバスを外す。
- 色: CSS 変数（`--color-bg`、`--color-signal`、`--color-accent-warm`）を読み、テーマの切り替えに追従する。作品詳細では `body` の `data-stage-tint` に主ジャンルの色の変数名を書く。
