# 02 体験、画面、デザイン

## 2.1 体験の流れ

利用者は、知らなかったゲームを見つけ、どのような遊びを楽しめるかを把握し、公式ストアや元記事へ進む。

主な導線は次のとおり。

```
ホーム ─┬─ アトラス（地図）上の点 ──────────┐
        ├─ 最近収録した作品 / 情報が充実した作品 ─┤
        ├─ コレクション ── コレクション詳細 ───┼─→ 作品詳細 ─┬─→ 公式ストア（外部）
        └─ 検索ボックス ── 作品一覧と検索 ─────┘             ├─→ 元記事（外部）
                                                             └─→ 関連作品 → 作品詳細
```

- 「新しく収録した日（収録日）」と「発売日」は常に別の項目として表示する。以前に発売された作品も、収録日が新しければ「最近収録」に並ぶ。
- サイトの表側ではゲームの魅力と探しやすさを優先する。LLM による運営方式の説明は運営説明ページ（`/about/`）にまとめる。

## 2.2 URL 一覧

すべての URL は `BASE_PATH` の配下に置く（[08-hosting-and-migration.md](08-hosting-and-migration.md)）。末尾にはスラッシュを付ける（`trailingSlash: 'always'`）。

| URL | 画面 | 生成方法 |
| - | - | - |
| `/` | ホーム | 静的 |
| `/games/` | 作品一覧と検索（1ページ目） | 静的。JS で検索 UI に切り替わる |
| `/games/page/{n}/` | 作品一覧の2ページ目以降 | 静的。JS が無効な環境のためのページ送り |
| `/games/{gameId}/` | 作品詳細（例: `/games/g_000123/`） | 静的。公開中の作品ごと |
| `/games/{mergedGameId}/` | 統合済みの旧 ID からの転送ページ | 静的。meta refresh と canonical で統合先へ案内する |
| `/articles/` | 記事一覧（新しい順、1ページ30件） | 静的 |
| `/articles/page/{n}/` | 記事一覧の2ページ目以降 | 静的 |
| `/articles/kind/{kind}/` | 記事の種別ごとの一覧（2ページ目以降は `/page/{n}/` を付ける） | 静的 |
| `/collections/` | コレクション一覧 | 静的 |
| `/collections/{collectionId}/` | コレクション詳細（例: `/collections/col_0001/`） | 静的 |
| `/about/` | 運営説明 | 静的（Markdown） |
| `/404.html` | 見つからないページ | 静的 |
| `/build-manifest.json` | 公開成果物の manifest | ビルド時に生成（[07](07-workflows-and-operations.md) §7.4） |
| `/atlas.json` | アトラス表示用のデータ | ビルド時に生成（§2.7.4） |
| `/sitemap-index.xml`、`/robots.txt` | クローラー向け | ビルド時に生成 |
| `/pagefind/` | 検索索引 | Pagefind が生成 |

URL には作品の表示名や slug を含めない。タイトルが変わっても URL は変わらない（[04-data-model.md](04-data-model.md) §4.2）。

## 2.3 画面ごとの仕様

### 2.3.1 共通レイアウト

- ヘッダー: ロゴ（Indie Atlas）、主要ナビゲーション（作品、記事、コレクション、運営説明）、検索ボタン（`/` キーで検索ページの入力欄へ移る）、表示テーマの切り替え（ライト、ダーク、システム設定に従う）。
- フッター: 運営説明へのリンク、出典と画像の扱いについての短い説明、情報の訂正依頼の窓口（[11](11-open-decisions.md) の D-10）、最終更新日。
- スキップリンク（「本文へ移動」）を先頭に置く。
- `<html lang="ja">` を指定する。外国語の原題や記事タイトルには、該当する要素に `lang` 属性を付ける。

### 2.3.2 ホーム（`/`）

上から次の順に並べる。

| 区画 | 内容 | 件数・並び順 |
| - | - | - |
| ヒーロー | アトラス（WebGL、§2.7）、キャッチコピー、検索ボックス、「リストで見る」リンク | 公開中の全作品を点で表示 |
| 最近収録した作品 | 作品カード | `addedAt` の新しい順に12件 |
| 最近情報が充実した作品 | 作品カードと、充実した内容の短い表示（例:「発売日が更新」「日本語対応を確認」） | `enrichedAt` の新しい順に8件。最近収録した作品の区画に出した作品は除く |
| コレクション | コレクションカード | `featured: true` のものを最大6件。足りなければ更新の新しい順で補う |
| まだあまり知られていない作品 | 作品カード | 関連記事が1件以下の公開作品から、日付をシードにした決定的な乱数で6件を選ぶ |

`enrichedAt` の定義は [04-data-model.md](04-data-model.md) §4.9 にある。

### 2.3.3 作品カード（共通部品）

| 要素 | 内容 | 値がない場合 |
| - | - | - |
| 画像 | ヘッダー画像。縦横比は 460:215 に固定し、`object-fit: cover` で収める | 共通のプレースホルダー画像 |
| 表示名 | `title.display` | （必須項目） |
| 原題 | 表示名と異なる場合だけ小さく表示する。`lang` 属性を付ける | 表示しない |
| 開発者 | 最初の1名。2名以上なら「ほか」を付ける | 「開発者不明」 |
| 発売 | 全体の発売状況のラベル（§2.4.2） | 「発売時期不明」 |
| 機種 | 機種アイコン（最大4つ、超えた分は「+n」） | 表示しない |
| 日本語対応 | バッジ（対応、一部、非対応、不明） | 「日本語: 不明」 |
| 収録日 | 「収録 2026/10/27」 | （必須項目） |

カード全体を作品詳細へのリンクにする。カード内に別のリンクを入れ子にしない。

### 2.3.4 作品一覧と検索（`/games/`）

- JS が無効な環境では、静的な一覧（収録日の新しい順、1ページ48件、ページ送り付き）を表示する。
- JS が有効なら、同じ場所を検索 UI に置き換える。
  - 入力欄: タイトル、原題、別名、読み、開発者名、タグ名、概要を対象にする。
  - フィルター: タグ（複数選択）、機種（複数選択）、発売状況、日本語対応、プレイ形式。
  - 並び順: 関連度（入力がある場合の既定）、収録日の新しい順（入力がない場合の既定）、発売日の新しい順。
  - 入力が空でもフィルターだけで一覧を出す（Pagefind の `search(null, { filters })`）。
  - 状態を URL のクエリと同期し（`?q=…&tag=roguelike&platform=switch`）、共有と戻る操作に対応する。`history.replaceState` を使い、入力のたびに履歴を増やさない。
- 結果は作品カードと同じ見た目にする。0件のときは条件の緩め方を提示する（フィルターを1つずつ外すボタン）。
- 検索の実装方法は [03-architecture.md](03-architecture.md) §3.6 にある。

### 2.3.5 作品詳細（`/games/{gameId}/`）

| 区画 | 内容 |
| - | - |
| ヘッダー | キーアート、表示名、原題、主な別名、開発者、パブリッシャー、全体の発売状況、ストアへのボタン（主要な操作）、公式サイトへのリンク |
| 概要 | 出典に基づく概要（60〜160字）。下に「出典」として参照元を列挙する |
| 特徴 | 3〜5項目の箇条書き。出典を併記する |
| 基本情報 | 表形式。開発、パブリッシャー、タグ、機種、発売（機種と地域ごと）、日本語対応（表示、字幕、音声）、プレイ人数と形式、公式サイト。行ごとに出典へのリンクと確認日を付ける |
| 発売情報の変遷 | 延期などで置き換わった発売情報を、時系列で折りたたみ表示する（ある場合のみ） |
| 関連記事 | 記事の種別（発表、ニュース、紹介、レビュー、インタビュー、開発日誌など）ごとにまとめる。各記事に媒体名、掲載日、言語、作品の扱い（主題、言及、まとめ記事内の紹介）、原文へのリンクを付ける |
| 関連作品 | 最大6件。各作品に関連の理由を一文で付ける |
| 収録コレクション | この作品を含むコレクション |
| ページ情報 | 収録日、ページの最終更新日、「情報の誤りを報告」 |

表示上の規則は次のとおり。

- 未確認の項目は推測で埋めず、「不明」と表示する（§2.4.3）。
- 概要と特徴の近くに「複数の出典をもとに要約した紹介です」と注記し、運営説明へリンクする。プレイしたかのようなレビューの文体は使わない（[05](05-sources-and-editorial-policy.md) §5.6）。
- 記事は原題のまま表示し、`lang` 属性を付ける。当サイトが書いた短い説明（120字以内）は、情報源の権利条件が許す場合だけ表示する。
- 構造化データとして JSON-LD の `VideoGame` を出力する。項目は `name`、`url`、`image`、`gamePlatform`、`author`（開発者）、`publisher`、`datePublished`（日単位で発売済みと確定している場合だけ）とする。

### 2.3.6 記事一覧（`/articles/`）

- 掲載日の新しい順に、1ページ30件を表示する。
- 各行に、記事タイトル（原題）、媒体名、掲載日、記事の種別、言語、関連作品（最大3件と「+n」）、原文へのリンクを表示する。
- 種別のタブ（すべて、発表、ニュース、紹介、レビュー、インタビュー、開発日誌、特集、まとめ）は静的なページ（`/articles/kind/{kind}/`）へのリンクにする。
- 媒体や言語での絞り込みは第4段階以降に検討する。

### 2.3.7 コレクション一覧と詳細

- 一覧: コレクションカード（タイトル、短い説明、代表作品3件の画像、作品数）を並べる。
- 詳細: タイトル、説明（Markdown）、選定条件、作品の一覧を表示する。作品ごとに、コレクションに含めた理由を一文で付ける。並び順はコレクションの `order` に従う。
- 第4段階で、コレクションに含まれる作品をアトラス上の星座として表示する（§2.7.3）。

### 2.3.8 運営説明（`/about/`）

`src/content/about.md` に置き、少なくとも次の内容を書く。

1. Indie Atlas の目的と収録対象（インディーと判定する方法を含む）
2. 情報の集め方。LLM が毎日自動で調査し、決定的な検証を通った情報だけを掲載していること
3. 概要や特徴の文章は出典をもとに自動で要約したもので、プレイした感想ではないこと
4. 出典、記事、画像の扱い（原文へのリンクを基本とし、全文は転載しないこと）
5. 「不明」の意味と、確認日の意味
6. 訂正依頼と掲載停止依頼の窓口
7. 運営者の連絡先

## 2.4 表示ルール

### 2.4.1 日付

| 対象 | 表示形式 | 例 |
| - | - | - |
| 収録日、確認日、掲載日 | `YYYY年M月D日`（カードでは `YYYY/MM/DD`） | 2026年10月27日 |
| 発売日（日まで分かる） | `YYYY年M月D日` | 2026年3月5日 |
| 発売日（月まで） | `YYYY年M月` | 2026年3月 |
| 発売日（四半期） | `YYYY年 第N四半期` | 2027年 第2四半期 |
| 発売日（半期） | `YYYY年 上半期` / `下半期` | 2027年 上半期 |
| 発売日（季節） | `YYYY年 春` など。出典の原文表記（`rawText`）も保持する | 2027年 春 |
| 発売日（年） | `YYYY年` | 2027年 |
| 発売日未定 | 「発売日未定」 | |

日付は日本時間（Asia/Tokyo）で表示する。保存は UTC の ISO 8601 で行う（[04](04-data-model.md) §4.1）。

### 2.4.2 発売状況のラベル

| 状態 | ラベル | 全体の状況を決める優先順位 |
| - | - | - |
| `released` | 発売中（`YYYY年M月D日` 発売） | 1（いずれかの機種で発売済みなら全体を発売中にする） |
| `early-access` | 早期アクセス中 | 2 |
| `upcoming` | 発売予定（`2027年 春`） | 3（最も早い予定日を表示） |
| `tba` | 発売日未定 | 4 |
| `cancelled` | 開発中止 | 5（全機種が中止の場合だけ） |
| `delisted` | 配信終了 | 6（全機種が配信終了の場合だけ） |

### 2.4.3 不明と未確認の表示

- 採用済みの Claim がない項目は「不明」と灰色の文字で表示する。空欄にも、推測した値にもしない。
- 「非対応」は根拠がある場合だけ表示する。根拠がなければ「不明」にする。
- 矛盾した情報がある項目でも、採用済みの値があればその値を表示し続ける。採用済みの値がないまま矛盾している項目だけを「確認中」と表示する（[06](06-update-pipeline.md) §6.8.2）。他の項目はそのまま表示する。

### 2.4.4 外部リンク

- 記事、ストア、公式サイトへのリンクは `target="_blank" rel="noopener"` にし、外部リンクであることをアイコンと読み上げ用のテキスト（「新しいタブで開く」）で示す。媒体に参照元を伝えるため、`noreferrer` は付けない。
- アフィリエイトリンクは使わない。

## 2.5 デザインの考え方

### 2.5.1 コンセプト

「夜空の星図を読む」体験を目指す。

- 作品は星（点）であり、タグの近さが位置の近さになる。
- コレクションは星座で、作品を線で結ぶ。
- 画面の背景は深い藍色。作品画像と、アクセントの光（青と琥珀）が浮かぶ。
- 演出は、静かで、ゆっくりで、読みを邪魔しないものにする。動きの主役は利用者の操作に反応する部分に限る。

### 2.5.2 見やすさを守る規則

| 規則 | 内容 |
| - | - |
| 文字を動く背景の上に直接置かない | WebGL の上に文字を置く場合は、不透明度80%以上の面かぼかし付きの面を下に敷く。最も明るい背景の上でもコントラスト比を満たすことを確認する |
| コントラスト | 本文は 4.5:1 以上、大きな文字と UI 部品は 3:1 以上（WCAG 2.2 AA） |
| 動き | `prefers-reduced-motion: reduce` の環境では自動のアニメーションを止め、静止画の1フレームだけを描く。画面遷移の演出も切る |
| 情報の主従 | 作品詳細と一覧では、演出よりも画像、タイトル、基本情報を優先する。WebGL は装飾に限る（§2.7.2） |
| 1ページ1キャンバス | WebGL のキャンバスは1ページに1つまでにする。カードの演出は CSS で行う |

## 2.6 デザインシステム【初期案】

値は出発点であり、第1段階（P1-06）で実際の画面を見て調整する。調整後の値は `src/styles/tokens.css` を正とする。

### 2.6.1 色

ダークテーマを既定にし、ライトテーマも用意する。CSS 変数で定義し、`[data-theme]` 属性と `prefers-color-scheme` で切り替える。

| トークン | ダーク | ライト | 用途 |
| - | - | - | - |
| `--color-bg` | `#0b1020` | `#f6f7fb` | ページの背景 |
| `--color-surface` | `#121a2e` | `#ffffff` | カード、パネル |
| `--color-surface-raised` | `#1a2440` | `#eef1f8` | ホバー時、ポップオーバー |
| `--color-border` | `#2a3556` | `#d5dbe8` | 境界線 |
| `--color-text` | `#e8ecf5` | `#141a2a` | 本文 |
| `--color-text-muted` | `#a3adc2` | `#4a5470` | 補足の文字 |
| `--color-accent` | `#7cc4ff` | `#0b63b6` | リンク、主要な操作 |
| `--color-accent-warm` | `#ffb86b` | `#a65300` | 強調、星の光 |
| `--color-positive` | `#7ee2a8` | `#1d7a46` | 「対応」バッジ |
| `--color-unknown` | `#8a93a8` | `#6b7489` | 「不明」の表示 |

アトラスの点の色には、タグの系統（genre）ごとに8色のカテゴリ色を用意する（`--atlas-c0` 〜 `--atlas-c7`）。色だけで情報を区別しない。凡例とツールチップの文字でも示す。

### 2.6.2 文字

| 用途 | 指定 |
| - | - |
| 本文（日本語） | `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", "Yu Gothic UI", Meiryo, system-ui, sans-serif`。日本語の Web フォントは読み込まない |
| 見出しの英数字 | Space Grotesk（OFL）の可変フォント。ラテン文字だけにサブセット化し、自前で配信する（woff2、40KB 以下）。日本語部分は本文のフォントで表示する |
| 数字 | `font-variant-numeric: tabular-nums`（表と日付） |
| 本文の大きさ | 16px 以上。`clamp(1rem, 0.95rem + 0.25vw, 1.0625rem)` |
| 見出し1 | `clamp(1.75rem, 1.2rem + 2.5vw, 3rem)`、太さ700 |
| 行の高さ | 本文 1.8、見出し 1.3 |
| 字間 | 本文 0.02em |
| 1行の長さ | 本文は最大 40rem（全角で約40字） |

### 2.6.3 余白、角丸、影、動き

- 余白は 4px を単位にする: `--space-1`（4px）〜 `--space-12`（96px）
- 角丸: `--radius-s`（6px）、`--radius-m`（12px）、`--radius-l`（20px）
- 影: ダークテーマでは影ではなく境界線と光の滲み（`box-shadow` に accent 色を低い不透明度で使う）で浮き上がりを表す
- 動き: 時間は `--dur-fast`（150ms）、`--dur-base`（250ms）、`--dur-slow`（400ms）。緩急は `--ease-out: cubic-bezier(0.2, 0.8, 0.2, 1)`

### 2.6.4 レイアウト

- カードの並び: `grid-template-columns: repeat(auto-fill, minmax(16rem, 1fr))`
- 作品詳細: 1024px 以上では、本文と側欄（基本情報、ストアボタン）の2列にする。それより狭い画面では1列にし、ストアボタンをヘッダーの直下に置く
- 区切りの幅: 640px、1024px、1440px

### 2.6.5 画面遷移

ブラウザの文書間 View Transitions を段階的な強化として使う。

```css
@view-transition { navigation: auto; }
@media (prefers-reduced-motion: reduce) {
  @view-transition { navigation: none; }
}
```

カードの画像と作品詳細のキーアートに、同じ `view-transition-name: game-{gameId}` を付け、一覧から詳細へ画像がつながって見えるようにする。クライアント側のルーター（Astro の `<ClientRouter />`）は使わない。WebGL と検索 UI の初期化を通常のページ読み込みと同じ流れで扱えるようにするためである。

### 2.6.6 部品の一覧

`src/components/` に次の部品を作る。

| 部品 | 役割 |
| - | - |
| `SiteHeader`、`SiteFooter`、`SkipLink`、`ThemeToggle` | 共通レイアウト |
| `GameCard`、`GameGrid` | 作品カードと並び |
| `ReleaseLabel`、`PartialDateText` | 発売状況と日付の表示（§2.4） |
| `PlatformList`、`JapaneseSupportBadge`、`PlayerModes` | 基本情報の表示 |
| `UnknownValue` | 「不明」「確認中」の表示 |
| `SourceRefs` | 出典の列挙（媒体名、リンク、確認日） |
| `ArticleItem`、`ArticleList` | 記事の表示 |
| `CollectionCard` | コレクションカード |
| `TagChip`、`FilterPanel`、`SearchBox`、`SearchResults` | 検索と絞り込み |
| `Pagination`、`Breadcrumbs`、`EmptyState` | 補助 |
| `AtlasHero` | ホームのアトラス（WebGL アイランド） |
| `DetailBackdrop` | 作品詳細のヘッダー背景（WebGL または CSS のグラデーション） |

UI フレームワーク（React、Svelte など）は導入しない。Astro コンポーネントと、素の TypeScript で書いた Custom Elements で作る。検索 UI が複雑になりすぎた場合に限り、Preact の導入を検討する。

## 2.7 WebGL の方針

### 2.7.1 使う場所と使わない場所

| 場所 | 演出 | 段階 |
| - | - | - |
| ホームのヒーロー | アトラス。公開中の全作品を点として配置した、操作できる星図（§2.7.3） | 第1段階 |
| 作品詳細のヘッダー | キーアートから抽出した色を使う、ゆっくり流れるノイズのグラデーション | 第1段階（CSS 版）、第4段階（WebGL 版） |
| コレクション詳細 | 収録作品だけを強調し、線で結んだ星座のミニマップ | 第4段階 |
| 一覧、検索、記事一覧 | 使わない（CSS の演出だけ） | — |

### 2.7.2 実装の方針

- ライブラリ: three.js は使わない。WebGL2 を直接使う小さな描画層（`src/scripts/gl/`）を書く。点群の描画と全画面のシェーダーだけなので、依存を増やさず JS の量を抑える。
- 読み込み: `AtlasHero` は、ブラウザが待機状態になってから（`requestIdleCallback`、なければ `setTimeout` で 1.5 秒後）動的 `import()` で読み込む。次のいずれかに当てはまる環境では読み込まず、静的な表示（§2.7.5）にする。
  - WebGL2 のコンテキストを作れない
  - `navigator.connection.saveData === true`
  - `prefers-reduced-motion: reduce`（この場合は静止画を1フレームだけ描く。操作は受け付ける）
- 描画:
  - コンテキストは `{ alpha: true, antialias: false, premultipliedAlpha: true, powerPreference: 'low-power' }` で作る。
  - 点は `gl.POINTS` とし、フラグメントシェーダーで中心から外へ柔らかく減衰する円を描く。ダークテーマでは加算合成で光らせ、ライトテーマでは通常の合成で濃い色の点にする。
  - 背景には、低い周波数のノイズによる星雲状のグラデーションを全画面の三角形1枚で描く。
  - デバイスピクセル比は、デスクトップで最大2、モバイル（`pointer: coarse`）で最大1.5に制限する。
- 性能の保護:
  - キャンバスが画面外にあるとき（IntersectionObserver）と、タブが非表示のとき（`visibilitychange`）は描画を止める。
  - 直近2秒の平均フレーム時間が 24ms を超えたらデバイスピクセル比を下げる。それでも 33ms を超えたら、アニメーションを止めて静止画にする。
  - `webglcontextlost` を受け取ったら静的な表示に切り替える。
- アクセシビリティ:
  - キャンバスには `aria-hidden="true"` を付け、Tab キーの移動対象にしない。
  - 同じ作品群に HTML でたどれるよう、ヒーローの直下に「アトラスの作品をリストで見る」（`/games/` へのリンク）を置く。
  - ツールチップは HTML の要素として描き、`role="tooltip"` を付ける。

### 2.7.3 アトラスの仕様

| 項目 | 仕様 |
| - | - |
| 点の位置 | ビルド時に、作品のタグベクトルを2次元に配置した座標（§2.7.4） |
| 点の色 | 作品の主なジャンル系タグに対応するカテゴリ色（上位8ジャンル。それ以外は中立色） |
| 点の大きさ | 3段階。情報の充実度（採用済みの主要項目の数）で決める |
| 待機中の動き | ゆっくり漂い、明滅する。reduced motion の環境では止める |
| 操作 | ドラッグで移動、ホイールとピンチで拡大縮小（0.5〜6倍）。点の上にポインターを置くか、タップするとツールチップを出す |
| ツールチップ | 画像、表示名、主なタグ3件、発売状況。クリック、2回目のタップ、Enter キーで作品詳細へ移る |
| 当たり判定 | CPU 側の一様グリッド（空間ハッシュ）で行う。GPU での判定はしない |
| 凡例 | 画面の隅に、色とジャンル名の対応を表示する |
| 星座（第4段階） | コレクションのチップにポインターを置くと、収録作品を線で結ぶ |

### 2.7.4 アトラスのデータ生成

`scripts/build/atlas-layout.ts` がビルド時に `.generated/site-data/atlas.json` を作り、公開サイトの `/atlas.json` として配信する。

1. 公開中の作品ごとに、採用済みのタグから特徴ベクトルを作る。重みは IDF に、タグの系統ごとの係数（genre 1.0、mechanic 0.8、play-style 0.7、theme 0.6、mood 0.6、setting 0.5、art-style 0.4）を掛けたもの。
2. `umap-js` で2次元に配置する。`nNeighbors = min(15, n - 1)`、`minDist = 0.3` とし、乱数は `config/runtime.json` の `atlas.seed` から作る決定的なものを渡す。
3. 作品が10件未満のときは UMAP を使わず、主ジャンルごとに円周上へ並べる。
4. 座標を [-1, 1] の範囲に正規化し、小数第3位で丸める。
5. 出力形式:

```json
{
  "v": 1,
  "palette": ["genre:roguelike", "genre:platformer", "..."],
  "points": [
    { "id": "g_000001", "x": 0.123, "y": -0.456, "c": 3, "s": 2, "t": "表示名", "i": "https://…/header.jpg", "tags": ["ローグライク", "デッキ構築"] }
  ]
}
```

作品が2,000件のとき、gzip 後に 100KB 以下を目安とする。超える場合は `i` と `tags` を別ファイルに分け、ツールチップを出すときに取得する。

作品が増えるたびに点の位置が大きく動く問題は、第4段階で前回の座標を初期値に使う方法を検討する（[09](09-roadmap.md) P4-06）。

- 「注目の作品」として、最近収録した作品の画像を6枚、星座のように配置したレイアウト

## 2.8 性能予算

モバイル（中位の Android 端末、4G 相当の回線）を基準に測る。第1段階では警告とし、第5段階で CI の合否条件にする。

| 指標 | ホーム | 作品詳細 | 作品一覧と検索 |
| - | - | - | - |
| LCP | 2.5 秒以下 | 2.0 秒以下 | 2.5 秒以下 |
| CLS | 0.1 以下 | 0.1 以下 | 0.1 以下 |
| INP | 200ms 以下 | 200ms 以下 | 200ms 以下 |
| 最初に読み込む JS（gzip 後） | 20KB 以下（アトラスは後から読み込む。本体 30KB 以下、データ 100KB 以下） | 20KB 以下 | 40KB 以下（Pagefind 本体と索引は除く） |
| CSS（gzip 後、全体） | 30KB 以下 | 同左 | 同左 |
| Lighthouse Performance | 85 以上 | 90 以上 | 85 以上 |
| Lighthouse Accessibility | 95 以上 | 95 以上 | 95 以上 |

- 画像には `width`、`height`、`loading="lazy"`、`decoding="async"` を付ける。最初に表示される画像（作品詳細のキーアート、ホームの最初の4枚）は `loading="eager"` と `fetchpriority="high"` にする。
- 外部の画像の扱いは [05](05-sources-and-editorial-policy.md) §5.4 に従う。

## 2.9 スマートフォンでの操作

受入基準10（スマートフォンで、検索から作品詳細、ストアまでたどれる）を満たすため、次を守る。

- 幅 360px から崩れずに表示できる。
- タップできる対象は 44×44px 以上にする。
- 検索のフィルターは、画面下から出るシートにまとめる。
- 作品詳細では、ストアボタンを最初の画面内に表示する。
- アトラスは、1本指で縦にスクロールしたときにページのスクロールを妨げない（`touch-action: pan-y`。拡大縮小と移動はピンチと2本指で操作する）。
