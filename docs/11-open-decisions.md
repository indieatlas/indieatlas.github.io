## 11.3 費用の見積もり（D-05 の判断材料）

[03](03-architecture.md) §3.5.2 の単価（DeepSeek V4.1 Flash のオフピーク: 入力 0.15 USD、出力 0.60 USD、キャッシュに当たった入力 0.003 USD。いずれも100万トークンあたり）での概算である。実際の値は P2-09 と P2-10 で測り、この節を更新する。

1つのタスク（`register-game` や `process-article`）を、次のように仮定する。

- ツールのループが8ターン
- ページを3件取得し、1件あたり約1万5千トークン（本文 2万字の上限まで）
- システムプロンプトなどの固定部分が約8千トークン
- 出力（思考を含む）が1ターンあたり約3,000トークン

| 内訳 | トークン数の目安 | 利用額の目安 |
| - | - | - |
| キャッシュに当たらない入力 | 約7万 | 約 0.011 USD |
| キャッシュに当たる入力（各ターンで会話の前半を送り直す分） | 約35万 | 約 0.001 USD |
| 出力 | 約2万4千 | 約 0.014 USD |
| 合計 | | 約 0.03 USD |

この仮定では、1回の実行（タスク12件と triage、plan）の利用額は約 0.4 USD、毎日実行して月に約 12 USD になる。ピークの時間帯に実行すると単価は2倍になる。

| 比べる対象 | 値 |
| - | - |
| 仮の予算 | 1回 1 USD、月 20 USD |
| Go のプランでの DeepSeek V4.1 Flash の上限 | 月 80 USD（5時間あたり 16 USD、1週間あたり 40 USD） |
| 実際に支払う額 | Go の月額 10 USD（Extra Usage を無効にしている場合） |

この見積もりでは、費用より実行時間（20分）とタスク数の上限が先に効く。P2-09 で1タスクあたりの所要時間を測り、`run.maxTasks` と `run.executeConcurrency` を調整する。

予算が足りずに途中で止まっても、探索のタスクは必ず実行されるよう、予算の一部を探索のために確保する（[06](06-update-pipeline.md) §6.5.4）。

## 11.4 OpenCode Go を直接呼び出すときの決まり

D-19 で、定期実行での利用は問題ないと決めた。そのうえで、2026-10-27 時点の [OpenCode Go のドキュメント](https://opencode.ai/docs/go/)が直接呼び出すアプリケーションに求めている次の2点を守る（[06](06-update-pipeline.md) §6.9.2）。

- 汎用の SDK 名ではなく、自分の User-Agent で名乗る（`IndieAtlasBot/0.1`）。
- 会話ごとに固定のセッション ID を `x-opencode-session` で送る。

あわせて、OpenCode Go の Extra Usage を無効にし、利用額がプランの上限を超えないようにする（[07](07-workflows-and-operations.md) §7.9）。
