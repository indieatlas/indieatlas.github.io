# 01 概要と基本原則

## 1.1 サービスの概要

| 項目 | 内容 |
| - | - |
| サービス名 | Indie Atlas【確定】 |
| リポジトリ名 | `indieatlas`【初期案】 |
| 種別 | インディーゲームのライブラリ兼ショーケース |
| 表示言語 | 日本語。海外の作品と情報源も扱う |
| 主な利用者 | 新しいインディーゲームを探している人。タイトルを知らなくても、遊び方や雰囲気から探したい人 |
| 運営形態 | LLM が定期実行で収集と整理を続け、人は方針の設定、初期データの確認、例外の判断を担う |

名前の「Atlas（地図帳）」をデザインの軸にする。作品を地図上の点や星として配置し、タグの近さが位置の近さになるように見せる。コレクションは星座のように作品を結ぶ。詳細は [02-ux-and-design.md](02-ux-and-design.md) にある。

## 1.2 提供する価値

利用者には次の3つを提供する。

1. 知らなかったゲームが見つかる。最新情報のカルーセル、最近収録した作品、テーマ別のコレクション、検索と絞り込みを入口にする。
2. どのような遊びを楽しめるかが分かる。出典に基づいた概要、特徴、基本情報、関連記事を作品ごとに見られる。
3. 公式ストアや元記事にすぐ進める。原文への導線を明確にする。

運営側では、LLM が次の仕事を続けることで、人手をかけずにサイトが育つことを目指す。

- 未収録作品の発見
- 作品情報の補完と変化の追跡（発売日の延期など）
- 外部記事と作品の関連づけ
- 関連作品の提示とコレクションの更新

## 1.3 試行期間で検証する仮説

| 番号 | 仮説 | 評価方法 |
| - | - | - |
| H1 | 自動収集で、利用者が知らなかった作品を継続して収録できる | 新規収録数と、報道の少ない作品の割合（[10-testing-and-acceptance.md](10-testing-and-acceptance.md) §10.6） |
| H2 | 出典に基づく整理で、作品を理解できる情報がそろう | 主要項目の充足率 |
| H3 | 関連記事と関連作品の提示に納得感がある | 抽出して人が評価する |
| H4 | 誤情報と重複を、運用できる水準に抑えられる | 訂正件数、重複件数 |
| H5 | 自動更新と公開が、費用の上限内で継続する | 公開の成功率、1回あたりの費用 |

## 1.4 スコープ

### 初期に実装するもの

- 作品一覧、検索と絞り込み、作品詳細、記事一覧、コレクション一覧と詳細、ホーム、運営説明
- 静的な全文検索と属性フィルター（Pagefind）
- WebGL を使った背景の演出。表示できない環境では静的な表示に切り替える
- 情報源の取得、LLM による抽出と調査、作品の同定、根拠の保存、重複の防止
- 定期実行、検証、コミット、ビルド、GitHub Pages への公開、失敗後の再開
- 状態に応じた仕事の選択、関連作品、コレクションの改善
- コーディングエージェントで手動でデータを集め、ページを作るためのスキル（[12-agent-skills.md](12-agent-skills.md)）

### 初期には実装しないもの

| 項目 | 理由・条件 |
| - | - |
| ユーザーアカウント、クラウド同期のお気に入り | 利用状況を見て追加する |
| 会話型の検索 | 同上 |
| 価格と価格履歴の網羅 | 同上 |
| 検索や閲覧の行動分析 | 計測方法を別途設計してから導入する |
| サイトコードの自動改善 | コンテンツ更新とは別の検証手順を設計してから扱う（[09-roadmap.md](09-roadmap.md) P5-04） |
| ユーザー投稿のレビュー | 対象外 |

## 1.5 基本原則

以下の原則は、すべての文書と実装の判断基準になる。

| 番号 | 原則 | 具体的な意味 |
| - | - | - |
| P1 | 根拠主義 | 公開する事実には出典を付ける。根拠のない値は「不明」と表示する |
| P2 | LLM は提案し、コードが採用する | LLM は構造化した提案だけを返す。スキーマ、出典、矛盾は決定的なコードが検証して採否を決める |
| P3 | 最小権限 | 外部の文章を読む LLM のジョブには、コミット権限も公開権限も渡さない。権限はジョブごとに必要な分だけ付与する |
| P4 | 再実行に対する安全性 | 同じ入力で何度実行しても、重複や不整合が生じない。ID は決定的に生成し、内容のハッシュで重複を防ぐ |
| P5 | ホストに依存しない | 公開 URL、ベースパス、デプロイの処理を設定として分離し、ホストを移しても収集処理やデータを変えずに済むようにする |
| P6 | 印象で確定しない | インディーかどうか、日本語に対応しているかなどは、根拠がそろうまで確定しない。LLM の推測だけで値を埋めない |
| P7 | 発見の多様性 | 毎回、報道の少ない作品や未収録作品の探索に予算を確保する。人気作品の更新だけで予算を使い切らない |
| P8 | 演出は豊かに、読みやすさは保つ | WebGL などの演出は段階的な強化として加える。文章の可読性、操作性、アクセシビリティ、表示速度を優先する |

## 1.6 方針の確定状況

| 項目 | 方針 | 確定度 |
| - | - | - |
| 対象 | インディーゲームのライブラリとショーケース | 【確定】 |
| 情報源 | 複数の媒体の記事、公式情報、ストアなど | 【確定】 |
| 自動化 | LLM が情報を収集し、整理と更新を続ける | 【確定】 |
| 実行基盤 | GitHub Actions の定期実行 | 【確定】 |
| 初期の公開先 | GitHub Pages | 【確定】 |
| 将来の公開先 | 手応えを確認してから、独自ドメインと別ホストへ移す | 【確定】 |
| サービス名 | Indie Atlas | 【確定】（2026-10-27） |
| デザイン | WebGL などを使い、豊かでありながら見やすさを損なわないモダンなデザイン | 【確定】（2026-10-27）。具体案は 02 |
| サイト生成 | Astro と TypeScript による静的生成 | 【初期案】 |
| 検索 | Pagefind による全文検索と属性フィルター | 【初期案】 |
| データ | 正規化した JSON を Git で管理する | 【初期案】 |
| 表示言語 | 日本語。海外の情報源と作品も扱う | 【初期案】 |
| 実行頻度 | まず毎日1回。運用を確認してから増やす | 【初期案】 |
| LLM | OpenCode Go の DeepSeek V4.1 Flash（`deepseek-v4.1-flash`）。接続部分は交換できるようにする | 【確定】（2026-10-27）。定期実行での利用とデータの送信先は問題ないと確認済み。API の細かな動作は P2-04 で確かめる |
| Web 検索 | 定期実行では使わない。登録した複数のゲームメディア、ストア、イベントの一覧から集める。情報源は人が必要に応じて追加する | 【確定】（2026-10-27） |
| 費用の上限 | 月額と1回あたりの両方を設定する | 【要決定】（11 の D-05） |

初期の自動更新では、作品情報、記事の関連づけ、関連作品、分類の候補、コレクションを主に扱う。機能やコードの改善も将来の拡張対象とするが、コンテンツ更新とは別の検証手順で扱う。
